# Project Memory Bank

The files in `memory-bank/` are concise project context for future maintenance. Keep them in English and update them when architecture, product behavior, operational requirements, or verified progress changes. They are documentation, not runtime configuration.

## Core files

- `projectbrief.md`: stable scope and constraints.
- `productContext.md`: user needs and intended workflows.
- `systemPatterns.md`: architecture and security boundaries.
- `techContext.md`: stack, commands, and environment notes.
- `activeContext.md`: current focus and immediate decisions.
- `progress.md`: completed capabilities, remaining work, and verification.

Read the relevant files before significant changes. Preserve facts about existing installations separately from plans. Record test results only when they were actually run, and replace stale status notes rather than accumulating contradictory history.
